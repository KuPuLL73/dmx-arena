# Заметки разработки DMX Arena

Рабочий журнал ветки `dev`. Сюда записываются анализ, решения и план работ.
Ветка создана от `main` на коммите `11b816d` (17.10.2026, портфолио-снимок беты).

## Правила работы

- Все правки идут в ветку `dev`, не в `main`.
- Перед правкой сначала проверяем, как это устроено в коде; текущий интерфейс и логику не ломаем.
- Ничего не публикуем и не деплоим без отдельного запроса.
- Секреты и токены не попадают в код, коммиты и заметки.

## Продуктовые решения

1. Английский — язык по умолчанию в приложении и в ответе бота на `/start`; если язык Telegram-пользователя определяется надёжно, интерфейс подстраивается под него.
2. Награды показываются без бонуса сета. Бонус сета действует на обычные игровые задания, но не на подписку и другие одноразовые задания.
3. Выполненные одноразовые задания уходят вниз. От задания «Добавить DMX в ник» можно отказаться — тогда оно тоже уходит вниз.
4. Очки клановой битвы засчитываются карте, на которой матч начался (игрок может зайти в последний час карты, матч длится до 4 минут и иногда заканчивается после смены карты).
5. Интерфейс остаётся вертикальным мобильным.

## Архитектура (кратко)

- `dist/` — Mini App на чистом JS: `app.js` (UI), `i18n.js` (RU/EN), 3D-персонаж (Three.js), каталог скинов.
- `tgcloud/` — Telegram Serverless: около 30 эндпоинтов с проверкой подписи Telegram, обработчик `/start` в `tgcloud/lib/welcome.js`, мост к воркеру в `tgcloud/lib/bridge.js`.
- `js-connector/` — Cloudflare Worker: коннектор к Pixel World / NotGames, хранилище SQLite в Durable Object, фоновый опрос игры.
- Корневые `*.mjs` — общая бизнес-логика (экономика, задания, карты, экипировка, турниры). Для воркера копируется в `js-connector/generated/` генератором.
- Python-файлы — резервная старая версия коннектора, в продакшне не используется.

### Проблема: очки при смене карты (решение 4)

Игра отдаёт только суммарный счётчик очков игрока. В `map-progress.mjs` есть окно 4 минуты после конца карты (`MATCH_FINISH_GRACE_MS`), но если прирост очков пришёл в момент, когда уже идёт следующая карта, подходят обе карты. Тогда очки помечаются как `map_overlap` и попадают в `record.pending` / `record.unassigned`. Дальше их никто не распределяет, а через 3 дня они удаляются — игрок теряет вклад за последний матч карты.

План (не начат, нужен ответ):
1. Узнать минимальную длительность матча N. Прирост, пришедший раньше чем через N минут после старта следующей карты, гарантированно относится к предыдущей карте — его можно засчитывать ей.
2. Если API игры отдаёт отдельные матчи со временем старта — брать время оттуда.
3. Тесты на граничные случаи в `test-map-progress.mjs`, затем перегенерировать `js-connector/generated/`.

Открытый вопрос: какая минимальная длительность матча / есть ли данные по отдельным матчам?

## Тестовый бот (отдельно от основного)

Цель: тестовый бот со своим Mini App, воркером и пустым хранилищем, чтобы разработка не задевала игроков.

Риск: в `tgcloud/lib/bridge.js` жёстко прописаны адрес боевого воркера и ID основного бота. Тестовый бот из текущего кода будет писать в **боевое** хранилище.

Значения основного окружения, зашитые в код:
- `tgcloud/lib/bridge.js` — `ORIGIN` воркера, `BOT_ID`, `CHANNEL_ID`;
- `tgcloud/lib/welcome.js` — `APP_LINK`, `APP_URL`, проверка `/start@DMXARENABOT`;
- `telegram-quest.mjs`, `js-connector/src/protocol.js` — канал @DMX_Core и его ID;
- `dist/app.js`, `dist/i18n.js` — ссылки на бота и канал в интерфейсе;
- `js-connector/wrangler.jsonc` — имя воркера;
- `js-connector/cloud-admin.mjs`, `serverless-login.mjs` — служебные скрипты.

План:
1. Вынести эти значения в конфиг окружения (`production` / `test`), не меняя поведение основного бота.
2. Владелец: создать тестового бота в @BotFather (+ Serverless), тестовый канал с ботом-админом, отдельный воркер (например `dmx-arena-connector-test`) со своими секретами.
3. Опубликовать тестовый экземпляр и проверить, что он пишет только в своё хранилище.

Заметки:
- Для теста лучше отдельная операторская сессия (`OPERATOR_SESSION`): одна сессия в двух местах может быть сброшена Telegram.
- Воркер на том же аккаунте Cloudflare делит бесплатные квоты с основным; фоновый опрос в тесте сделать реже или отключаемым.

## Локальная проверка

```sh
npm test                                   # основные тесты: без сети и ключей (27.10 — все прошли)
npm ci --prefix js-connector && npm test --prefix js-connector
npm ci && npx playwright install chromium && npm run qa:beta   # браузерный прогон на моках
```

Не запускать без необходимости: `serverless:deploy` (публикация), `launch:prepare` (сброс наград и прогресса), `npm start` (нужна настройка бота).
